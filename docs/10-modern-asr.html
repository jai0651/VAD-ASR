10.2Subwords: the cheapest large win

Module 2's transcription of a real utterance was:

hyp: he inl san er mianthes tlen kis roint the stieia sord meai wen
ref: but in less than five minutes the staircase groaned beneath an
     extraordinary weight

Look at what kind of error that is. It is not acoustically stupid — the rhythm and many vowels are right. It is orthographically impossible: no English word looks like "mianthes". A character model has to learn spelling through the acoustic model, from scratch, from a few hours of audio.

BPE (src/asr/tokenizer.py, ~150 lines, no dependency) fixes this structurally. Start with characters; repeatedly merge the most frequent adjacent pair; stop at V tokens. The model then emits ▁recogn + ition as atomic units and cannot misspell inside them. Targets also get ~3× shorter, which directly cuts decoder steps — i.e. latency.

The detail that makes it lossless The ▁ word-start marker. Without it, "▁a ▁cat" and "▁ac at" decode to the same string and detokenization has to guess. With it, decoding is "concatenate everything, turn ▁ into a space" — exact, always.

10.3The Conformer block

x ← x + ½·FFN(x) macaron: half a feed-forward before… x ← x + MHSA(x) global context, RELATIVE positions x ← x + Conv(x) local context, depthwise, kernel 31 ≈ 150 ms x ← x + ½·FFN(x) …and half after x ← LayerNorm(x)

The premise is that self-attention and convolution are complementary, not competing. Attention is excellent at long-range dependencies and bad at the short, translation-invariant patterns that carry phonetic identity — formant transitions, plosive bursts. A depthwise conv is the reverse. Conformer uses both in every block instead of choosing.

Relative positional attention

Absolute sinusoids tell the model "this is frame 412", which is meaningless for speech; what matters is that one frame is 30 ms after another. In the Transformer-XL formulation the score decomposes into a content-content term and a content-position term, and the position term is produced by shifting a single positional matrix rather than indexing per pair:

scores = (q+u)·kᵀ  +  rel_shift( (q+v)·pᵀ )

rel_shift is pure index bookkeeping: row t arrives holding scores against offsets +(T−1)…−(T−1) and must end up holding scores against absolute keys 0…T−1. Padding by one column and reshaping performs that diagonal shift in two ops instead of a gather. This is why a Conformer trained on 10 s utterances still works on 30 s ones.

×4 conv subsampling

Two strided 2-D convs turn 100 frames/s into 25. Not only a speed trick: attention is O(T²), so ×4 subsampling is a 16× reduction in attention cost. It is what makes self-attention affordable for audio at all. (FastConformer pushes this to ×8 with depthwise-separable convs — the single biggest remaining efficiency win available to this code.)

10.4Streaming, and the test that proves it

Module 2's BiGRU could not stream at any setting: bidirectional means the first frame's output depends on the last frame's input. Module 6 streams by construction, using two mechanisms that must both hold:

  • Dynamic chunk masking. Each frame may attend only within its own chunk plus some chunks of history. During training the chunk size is resampled every batch (half the batches use full context), so one model learns every operating point. At inference you pick the chunk — 640 ms for responsiveness, 0 for best WER — with no retraining. The alternative is training and shipping two models.
  • Causal depthwise convolution. Left padding only. Without it, the conv module leaks ~15 frames of future into every block, and the chunk mask is a fiction.
Claims about streaming need a test, not a comment test_chunked_encoder_is_truly_causal encodes 400 frames, then encodes just the first 200, and asserts the overlapping outputs are identical. If appending future audio changes an already-emitted frame, every streaming latency number you report is a lie. This is the easiest thing in a Conformer to get silently wrong — one wrong mask broadcast does it.

And it is guarded by test_non_causal_conv_breaks_causality, which asserts the same comparison fails with a symmetric kernel. A test that passes for the wrong reason is worse than no test; this proves the first one is actually measuring something.

10.5Two heads on one encoder

feats ─▶ Conformer encoder ─┬─▶ CTC head ─▶ L_ctc alignment └─▶ Transformer dec ─▶ L_att language L = 0.3·L_ctc + 0.7·L_att

CTC's defining assumption is conditional independence: given the audio, each frame's label is predicted without reference to its neighbours. That is what makes the loss a tractable dynamic program, and it is exactly why "mianthes" was possible — nothing in the model knows a 'q' is followed by a 'u'. An autoregressive decoder is precisely the missing piece.

Each head fixes the other's failure mode. CTC is monotonic by construction, so it stops the attention from wandering or looping — the same failure Module 4's TTS needed guided attention to avoid. The decoder supplies the implicit language model. One encoder pays for both.

Attention rescoring

Decoding uses the same split in two passes: CTC prefix beam search proposes an n-best list (fast, monotonic, streaming-compatible), then the decoder scores all n hypotheses in a single batched forward. That is far cheaper than an autoregressive beam search, which evaluates the decoder once per output token per beam.

10.6The CTC plateau — a debugging story worth keeping

First real run: CTC loss dropped 16.8 → 5.5 in fifty steps and then sat there. 800 steps later it was still ~5.0. With a 256-token vocabulary, ln(256) = 5.55 — so the model had learned almost nothing, while the attention loss fell steadily to 4.15 (it was learning unigram statistics from the text alone, which needs no audio at all).

That looks exactly like a broken gradient path, and there was a prime suspect: aten::_ctc_loss has no MPS kernel, so we route that one op through the CPU. A direct check ruled it out — CTC-only gradients on MPS matched CPU to three digits at every depth. The real answer came from the standard diagnostic instead:

60 utterances, tiny modelstep 100step 200step 300step 400
CTC loss, no augmentation5.054.441.170.13
CTC loss, SpecAugment from step 05.064.783.501.06

Two facts fall out. First, the model is fine — with no augmentation it goes from 5.05 to 0.13 and transcribes its training set perfectly. Second, CTC has a characteristic plateau: it sits near uniform for a few hundred steps while it hunts for any alignment, then falls off a cliff. On 60 utterances that took ~250 steps; on 2300 with augmentation and chunk masking it takes thousands. The 800-step run had simply ended during the plateau.

Two things this changed in the code Augmentation warmup (AUG_START): regularising a model that has not yet learned the task only lengthens the plateau, so SpecAugment and noise now switch on after the alignment forms. And the diagnostic itself is worth keeping as a habit — before a long run, check that the model can overfit 60 utterances. It distinguishes "stalled" from "broken" in four minutes, and it is why test_overfits_a_tiny_batch exists in the test suite.

Four things fall out of that table:

  • The architecture change halved the error on identical data. WER 1.076 → 0.607 (44% relative), CER 0.658 → 0.276 (58% relative). No extra audio, no extra epochs of it — just Conformer, subwords, a second head, and the recipe.
  • Streaming is nearly free. 0.607 → 0.627 for 640 ms of lookahead: 3% relative. Dynamic chunk training delivered on its promise, and Module 2 could not do this at any cost.
  • It is also 2.7× faster (RTF 0.011 → 0.004), despite being 2× bigger. That is the ×4 subsampling: attention is O(T²), so quartering T is the dominant term.
  • Whisper is still 18× better — on 165 000× the data. That ratio is the answer to "what's left?".

Module 2 produces phoneme soup. Module 6 produces English — "he gave work", "still has", "for him" are exactly right, and the errors are now word-shaped rather than letter-shaped, which is precisely what subwords plus an autoregressive decoder are supposed to buy. (Note Whisper's one error: "alignment" for "allurement" — a language-model error, not an acoustic one. Even 680 000 hours guesses when the acoustics are ambiguous.)

A recipe step that backfired, and the fix Checkpoint averaging hurt: averaging the last 5 checkpoints gave WER 0.659 against a best single checkpoint of 0.612. The premise of averaging is that SGD near convergence orbits one basin — but with EVAL_EVERY=1000 those five checkpoints spanned the whole run (WER 0.86 → 0.61). They were different basins, not one orbit, and averaging a half-trained model into a trained one is just damage. Fixed by averaging the best-K by held-out WER (what ESPnet's n-best averaging does) and keeping the result only if it actually wins. The guard mattered more than the technique: the script never shipped the worse model, because it always re-scores before saving.

10.8What is still not state of the art

Honest list, in order of how much it costs you:

  1. Data. This is now the dominant term, which was the goal. LibriSpeech dev-clean is 4 h; Parakeet saw ~640 k h. See §10.9.
  2. No transducer head. Parakeet's TDT emits a token and a duration per step, skipping frames instead of emitting blanks. That is the throughput trick, and it needs a transducer loss we don't have.
  3. ×4, not ×8 subsampling. FastConformer's depthwise-separable ×8 front-end roughly halves encoder cost at equal accuracy.
  4. No external language model. Shallow fusion with an n-gram or a small neural LM during beam search is a standard 5–15% relative WER win.
  5. fp32 only. bf16 would roughly double throughput on supported hardware.
  6. No BPE dropout, no SpecAugment++ / adaptive masking.

Two notes on scaling that are easy to get wrong:

  • Grow the vocabulary with the data. 256 subwords suits a few hours; 100 h wants ~1024, and 960 h wants 2048–5000. Too large a vocabulary on too little data leaves most tokens with a handful of examples each.
  • Grow the model with the data, not before it. SIZE=small is ~30 M parameters. On 4 hours that memorises the speakers; on 100 h it is about right; on 960 h go to base. Scaling the model first just produces a more confident overfit.

The script's final report prints the three numbers that characterise a streaming recognizer, and the gaps between them are the interesting part: CTC greedy, + attention rescoring (what the second head buys), and streaming at a fixed chunk (what the latency costs).
