The Neural Vocoder

Module 7: removing the one ceiling in this repo that no amount of training data can lift — Griffin-Lim's guessed phase — by predicting phase instead of iterating toward it.

← contents · the crux · module 4 tts · state of the art

11.1The ceiling

Module 0 computed |X|² and threw the phase away. Module 4's Griffin-Lim gets it back by exploiting frame overlap: guess a phase, inverse transform, re-measure the phase, keep our magnitude, repeat. After 60 rounds the (magnitude, phase) pair is self-consistent.

Self-consistent is not correct. There are many phase fields consistent with a given magnitude spectrogram, and the one Griffin-Lim converges to is generally not the one the speaker produced. That mismatch is audible as the phasey, metallic, slightly-underwater quality of every Griffin-Lim sample in outputs/.

Why this is different from every other gap in the repo §8 separated five kinds of gap — data, scale, architecture, recipe, inference. Almost everywhere, more data helps. Here it cannot, at any quantity, because the limitation is not in a learned component at all. Griffin-Lim has zero parameters. You could train the Tacotron on ten thousand hours and the output would still sound phasey. That is what makes this the highest-value single change available to Module 4 — and why it is worth doing before any more TTS data work.

The insight behind the spectral family is that the hard part was never "make a waveform". The ISTFT does that exactly, for free, and has since 1977. The hard part was only ever "know the phase". So predict the phase, run the exact inverse, and stop paying a network to re-derive arithmetic we already have.

Three reasons it is the right choice for this repo specifically:

  • It shares Module 0's grid. n_fft 512, window 400, hop 160 — identical to src/audio/features.py. The mels the Tacotron already emits drop straight in, with no retraining of Module 4.
  • It is affordable. Roughly two orders of magnitude less compute per second of audio, which is what matters when the target is a laptop CPU inside a turn-taking latency budget.
  • It degrades gracefully. Trained on a multi-resolution STFT loss alone, with no discriminators, it already clears Griffin-Lim. Adversarial training becomes a later quality upgrade rather than a prerequisite — so there is a working artifact at every stage, instead of only at the end.

11.3The architecture

log-mel (B, T, 80) │ ▼ Conv1d(80 → d, k=7) + LayerNorm │ ▼ N × ConvNeXt block depthwise k=7 → LN → Linear(d,3d) → GELU → Linear(3d,d) → ·γ │ ▼ Linear(d → 2·257) split: log-magnitude | phase angle │ ▼ S = exp(mag) · e^(i·phase) │ ▼ exact inverse STFT overlap-add, no learning waveform (B, T·160 + 240)

No attention. A vocoder needs a receptive field of a few tens of milliseconds — enough to place a glottal pulse — not a sentence. Convolutions supply that far more cheaply, which is why every production vocoder is convolutional.

Two details that are not decoration:

  • Predict LOG magnitude. Spectra span ~120 dB. A linear head either saturates on the quiet parts or explodes on the loud ones. The clamp at log(1e3) is a hard safety rail: one exp(30) produces inf and poisons the entire batch's gradients — tested by test_magnitude_clamp_prevents_inf.
  • Layer scale γ initialised near zero. Each ConvNeXt block starts as approximately the identity, which is what lets a deep stack train stably without warmup tricks.

11.4The inverse STFT has to be exact

The whole premise is that the network only has to learn phase. If the overlap-add is even slightly lossy, the model spends its capacity compensating for our arithmetic instead, and every quality number measures the wrong thing. So the reconstruction is asserted to machine precision (measured: 8.9 × 10⁻⁸).

Module 4's istft loops over frames in Python — fine for synthesising one utterance, hopeless inside a training step. The fast version uses F.fold, which is the transpose of the unfold that created the frames — and the transpose of framing is overlap-add. One fused, differentiable op instead of a loop. A test asserts the two agree, so the optimisation is provably not a behaviour change.

11.5The loss, and the term that is deliberately absent

Multi-resolution STFT distance at three window sizes (512/1024/256). A single resolution is a trap: a short window has good time resolution and poor frequency resolution, so a model trained on it gets pitch subtly wrong; a long window is the reverse and smears transients. Three at once leaves an error nowhere to hide.

Per resolution, two complementary terms:

  • Spectral convergence ‖|S|−|Ŝ|‖F / ‖|S|‖F — relative, so it is dominated by loud, high-energy regions.
  • Log-magnitude L1 — the reverse: log compresses the range so quiet detail (breath, fricatives, decay tails) gets a vote.
There is no phase term. That's the design. Nothing in the loss supervises phase directly. The model is free to choose any phase that makes the magnitudes come out right after overlap-add — and since overlapping frames share 240 of their 400 samples, only mutually consistent phase fields survive that constraint. Consistency emerges from the ISTFT's own redundancy rather than being imposed. Supervising raw phase angles directly is famously ineffective anyway: phase is circular, so 0.01 and 2π−0.01 are adjacent but look maximally far apart to an L1 loss.

11.6The experiment

scripts/12_train_vocoder.py is deliberately airtight: both vocoders receive the exact same log-mel of a held-out utterance and must produce a waveform. Nothing else differs, so any gap is attributable to phase modelling and nothing else.

I picked a rigged metric, and the measurement caught it The first version of this experiment reported only multi-resolution STFT distance — the training loss. The reasoning was that Griffin-Lim does not train, so neither side gains an advantage. That reasoning is wrong. Griffin-Lim's entire algorithm is "iterate until the magnitudes are consistent", and MR-STFT distance is a magnitude metric. Scoring the two vocoders on it asks Griffin-Lim how well it did at its own objective, while being nearly blind to the one thing it gets wrong — the phase. The fix is to report a time-domain metric alongside it, where a wrong phase cannot hide: SI-SDR.

Result after 12 000 steps (1.55M params, dev-clean, no discriminators)

vocodermr-stft (magnitude) ↓SI-SDR (phase-sensitive) ↑
Griffin-Lim, 60 iters, 0 params0.858−37.6 dB
ISTFT vocoder, 1.55M params1.010−32.2 dB

Exactly the split the theory predicts. Griffin-Lim wins on magnitude, because that is what it optimises. The neural vocoder wins by 5.4 dB on SI-SDR, because it predicts phase rather than guessing it — which is the entire thesis of the module.

But the quality claim is not yet earned. −32 dB SI-SDR is poor in absolute terms, and losing on magnitude means this model is simply undertrained: 12 000 steps on 1-second crops with a 1.55M model against Vocos's ~1M steps with discriminators. What is verified here is the pipeline and the architecture — exact ISTFT, correct gradients, the predicted phase advantage appearing on the metric that can see it. Turning that into audible superiority needs a longer run and adversarial training, which is a GPU job rather than a laptop one.

The script also writes outputs/12_true.wav, 12_neural.wav and 12_griffinlim.wav. For a vocoder, listening is the evaluation that actually counts; the numbers exist to stop you fooling yourself between listens.

11.7What this still isn't

  1. No discriminators. The multi-period and multi-scale discriminators from HiFi-GAN are what take a vocoder from "clearly better than Griffin-Lim" to "indistinguishable from the original". They are the next upgrade, and they are why real vocoder training is slow.
  2. 16 kHz. Modern TTS ships 24 kHz or 44.1 kHz; our whole pipeline is 16 kHz because that is what ASR wants.
  3. Trained on read speech. LibriSpeech only. Singing, whispering and heavy emotion are out of distribution.
  4. Still a two-stage TTS. Mel is an information bottleneck between the acoustic model and the vocoder. Codec-LM systems (Orpheus, Chatterbox) remove that seam entirely — see §8.5.

11.8Using it

# train (dev-clean is enough to beat Griffin-Lim; more data still helps)
uv run python scripts/12_train_vocoder.py
STEPS=20000 DIM=256 BLOCKS=8 uv run python scripts/12_train_vocoder.py
SPLIT=train-clean-100 DOWNLOAD=1 STEPS=40000 uv run python scripts/12_train_vocoder.py

# then listen to the A/B it writes
open outputs/12_griffinlim.wav outputs/12_neural.wav outputs/12_true.wav

Because it consumes the same 80-mel grid as everything else in the repo, the vocoder is not TTS-specific: anything that produces a Module 0 log-mel can be turned back into audio with it.
