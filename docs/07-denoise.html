Noise Suppression

Module 5: the stage in front of everything. A streaming denoiser written by hand from the classical statistics — and the measurement that proves it helps the VAD, and can hurt the ASR.

← hub · decisions

7.1Why this stage exists

Every module before this one assumed the microphone was reasonably clean. It never is. And the failure mode isn't "the transcript has a typo" — it's the bug Module 1b hit: room ambience read as speech, so turns never closed and phantom barge-ins flushed every reply. Noise doesn't degrade a voice agent gracefully; it breaks the turn-taking layer first, and by the time you notice the transcript quality you have already lost the conversation.

Noise suppression is also the one place in this pipeline where a non-neural algorithm is still genuinely competitive, which makes it the best remaining thing to write by hand. The classical method is not a toy version of the real thing — it was the real thing on every phone and headset for twenty years, and it is still the baseline every paper reports against.

7.2The model of the world

Assume noise adds in the STFT domain, per frequency bin, per frame:

Y[k,t] = S[k,t] + N[k,t] noisy speech noise

and estimate a real, non-negative gain G[k,t] ∈ [G_min, 1] to apply: Ŝ = G · Y. Phase is left untouched. That single simplification is what makes the classical method tractable — and it is exactly the ceiling that modern complex-domain models break through.

Everything then reduces to three questions, each answered by one named algorithm. They live in src/denoise/spectral.py.

1. How loud is the noise, right now, per bin?

You can't ask the user to be quiet, so you have to estimate the noise floor while they talk. The trick is that speech is intermittent: in any given band, the running minimum of the smoothed power is a decent proxy for the noise floor. Where the current power towers over that minimum you're probably in speech, so you freeze the noise estimate; elsewhere you update it. That's MCRA (Minima-Controlled Recursive Averaging), with Doblinger's continuous minimum tracker so there's no history buffer — one multiply-add per bin, which is why this ships on DSPs.

The failure this hides Recursive averaging has a nasty trap: if the estimate is ever initialised high — e.g. the stream starts mid-word, which for a voice agent is the normal case — the freeze-during-speech rule keeps it high forever, and a too-high noise floor over-suppresses precisely the bands speech lives in. Measured here on a LibriSpeech crop starting mid-utterance: +9 dB of bias below 500 Hz. The fix is Martin's minimum statistics as a safety net — cap the estimate at 1.5 × S_min, because the minimum of the smoothed power cannot be far above the true floor. That one line took speech attenuation from 5.1 dB to 4.2 dB, and the parameter sweep that followed took it to 1.7 dB.

2. How much speech is in this bin?

The a-priori SNR ξ. Estimating it from the current frame alone is horribly noisy and produces musical noise — random isolated tone bursts, the artifact everyone recognises from 1990s spectral subtraction. Ephraim & Malah's decision-directed estimator averages the previous frame's enhanced SNR with this frame's raw estimate:

ξ = α·(Ĝ²_prev · γ_prev)  +  (1-α)·max(γ - 1, 0)      α = 0.98

That temporal smoothing is the single most important line in the file. It is also the reason α is 0.98 and not 0.9: the gain is allowed to react slowly, because a gain that reacts per-frame is musical noise.

3. Given ξ, what gain is optimal?

log-MMSE (Ephraim & Malah 1985): minimise squared error on the log spectrum rather than the linear one, because loudness perception is logarithmic. The result is built from the exponential integral E₁ — which we implement with the Abramowitz & Stegun rational approximations, since there is no scipy here:

v = ξ/(1+ξ) · γ
G_lsa = ξ/(1+ξ) · exp(½ · E₁(v))

4. …and the refinement that kills the residual warble

OM-LSA (Cohen 2003) blends the gain toward the floor using the speech-presence probability: G = G_lsap · G_min(1-p).

A bug worth remembering The blend exponent must be a real speech-presence probability, not the MCRA indicator. They answer different questions: the MCRA indicator asks "is this band above its own long-run minimum?" (fine for deciding whether to update a noise estimate), while the gain needs "given ξ and γ, how likely is speech here now?" — Cohen's estimator p = 1/(1 + q/(1-q)·(1+ξ)·e-v). Using the indicator directly cost 5 dB of speech attenuation, because it never saturates to 1 inside speech, so every voiced band got dragged toward the floor.

7.3The streaming contract

Shared by every engine in src/denoise/: feed consecutive, non-overlapping blocks in stream order; process() buffers internally to the engine's hop and returns only fully reconstructed hops, so it may return fewer samples than you gave it. Output sample i still corresponds to input sample i — it just arrives delay samples later. That lag is the algorithmic latency, and it is not a free parameter:

engineframingdelaywhy
spectral512 / hop 256, sqrt-Hann256 (16 ms) periodic Hann applied on analysis and synthesis multiplies back to a full Hann, which sums to exactly 1.0 at 50% overlap — perfect reconstruction, no normalisation pass
gtcrn512 / hop 256, sqrt-Hann256 (16 ms) same shell; the model is frame-in/frame-out with cached state
dtln512 / hop 128, rectangular384 (24 ms) trained for 75% overlap with the network itself learning to emit frames that overlap-add correctly. Run it at 50% and reconstruction breaks — measured 19 dB SNR in, 6 dB out. The shift is part of the model, not a tuning knob.

tests/test_denoise.py asserts the declared delay by sending an impulse through and finding where it lands. That test exists because the delay is what keeps the raw and cleaned streams aligned in denoise_target=vad, and a silent 16 ms drift there clips word onsets — the exact bug pre-roll exists to prevent.

7.4Where the stage goes, and who gets clean audio

mic ─▶ [DENOISE] ─▶ VAD ─▶ endpointer ─▶ ASR ─▶ LLM ─▶ TTS │ └─ denoise_target = "both" → VAD and ASR both get cleaned audio denoise_target = "vad" → VAD gets cleaned, ASR gets the aligned ORIGINAL

Mechanically the denoiser is attached as a decorator around the VAD engine (src/pipeline/denoise.py). Not an aesthetic choice: the VAD is the single point every microphone sample flows through, and the endpointer buffers exactly the sample arrays the VAD hands back — so wrapping the VAD is the only place where one object can control both what gets scored and what gets transcribed.

ΔSNR alone is a bad summary — an engine that attenuates everything by 20 dB scores fine on "noise removed" — so the benchmark reports pause-attenuation and speech-attenuation separately. Note the honest read: on stationary synthetic noise the hand-written algorithm is competitive. That is the regime it was designed for. Where it loses is covered in §8.5: non-stationary noise (a door slam, a keyboard, another person talking) is invisible to a minimum-statistics tracker and obvious to a trained model.

The counter-intuitive result At the SNR where you most want help, the classical front-end hurts Whisper — 0.068 → 0.079 CER. Whisper was trained on 680k hours of real-world audio including noise, so it has learned to hear through it; a denoiser hands it spectral artifacts it has never seen. That is an out-of-distribution input, the same failure mode as Module 1b, arriving from the other direction. GTCRN is neutral (0.070) because it damages speech less. Meanwhile the scratch ASR — trained on clean LibriSpeech — mildly prefers denoised input.

Hence the default VOICE_DENOISE_TARGET=vad: take the certain win (VAD, every engine, every SNR), skip the uncertain loss (ASR).

7.6Config

# the from-scratch engine, cleaning only what the VAD sees (defaults)
uv run python -m server.app

# production engine, everything downstream gets cleaned audio
VOICE_DENOISE_ENGINE=gtcrn VOICE_DENOISE_TARGET=both uv run python -m server.app

# off, to measure the difference on your own voice
VOICE_DENOISE_ENGINE=none uv run python -m server.app

# keep more residual noise (gain floor); lower = gentler
VOICE_DENOISE_ATTEN_DB=12 uv run python -m server.app

The browser client shows noise removed (dB) next to P(speech). Healthy: a lot of dB while your room is idle, only a few while you talk. Consistently high while you talk means the suppressor is eating speech.

7.7What this doesn't do

  • Echo cancellation (AEC). Completely different problem: the interference is a signal you already have (your own TTS output), so you cancel it adaptively rather than estimate it statistically. The browser's WebRTC AEC does it for us; a telephony deployment must do it itself.
  • Dereverberation. Reverb is convolutive, not additive — our whole model of the world is wrong for it. Needs WPE or a model trained on RIRs.
  • Speaker separation. Babble is still our worst case (P(speech) 0.39–0.52 even after suppression) because the interferer is speech. That needs target-speaker extraction conditioned on an enrolment embedding, which is a different architecture entirely.
  • Wideband/fullband. Everything here is 16 kHz. Telephony is 8 kHz μ-law and consumer audio is 48 kHz; both change which model wins.

The standalone denoiser/ project in this repo is the same technology pointed at a different target: your real mic → cleaned → a virtual audio device, so Zoom/Meet/a softphone hears only your voice. It carries the VoiceBank-DEMAND benchmark (PESQ/STOI/SI-SDR on real recorded noise) that justified picking GTCRN as the production default here.
